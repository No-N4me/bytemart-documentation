# Команды

ssAntiCheat имеет два вида команд: **консольные/RCON**-команды с префиксом
`ssac.` и **внутриигровые чат**-команды с префиксом `!` (настраивается через
[`CommandPrefix`](configuration.md#top-level-keys)).

Доступ к консоли и RCON по определению является доступом администратора,
поэтому команды `ssac.` не требуют дополнительных прав. Чат-команды проверяют,
что вы являетесь **администратором сервера** (`enablecheats`), и в противном
случае молча ничего не делают.

## Команды консоли / RCON

| Команда | Каналы | Описание |
| ------- | -------- | ----------- |
| `ssac.help [page]` | Console, RCON | Постраничный список всех зарегистрированных команд. |
| `ssac.status` | Console, RCON | Лицензия, ID сервера и статус телеметрии дашборда. |
| `ssac.detections` | Console, RCON | Список последних обнаружений, сгруппированных по Steam ID. |
| `ssac.pendingbans` | Console, RCON | Список игроков, поставленных в очередь на следующую волну банов. |
| `ssac.banwave` | Console, RCON | Немедленно выполнить ожидающую волну банов. |
| `ssac.clearbanwave` | Console, RCON | Сбросить все ожидающие баны, никого не забанив. |
| `ssac.ban <steamid> [r=<reason>] [d=<duration>]` | Console, RCON | Забанить игрока. |
| `ssac.unban <ban-id>` | Console, RCON | Отменить бан по его ID. |
| `ssac.testdetection [steamid] [module]` | Console, RCON | Отправить симулированное обнаружение на дашборд. |
| `ssac.go [steamid]` | Console | Перейти в режим наблюдателя за игроком — указанным, или последним обнаруженным. |
| `ssac.command <reason> <command...>` | Console | Выполнить консольную команду от своего имени, с записью в журнал. |

`ssac.go` и `ssac.command` действуют на *вашего* персонажа, поэтому они
работают только из внутриигровой консоли — за сессией RCON нет персонажа.

### `ssac.status`

Первое, что стоит выполнить после установки, и первое, что попросит запустить
поддержка. Команда выводит версию плагина, прошла ли лицензия аутентификацию,
ID этого сервера, карту и имя сервера, а также — если телеметрия дашборда
включена — конечную точку, зарегистрировался ли сервер, результат последней
отправки и глубину очереди.

```bash
ssac.status
```

Ненулевая глубина очереди, которая никогда не уменьшается, означает, что
конечная точка дашборда недоступна или отклоняет ваши события.

### `ssac.detections`

Выводит список обнаружений, хранящихся в памяти (примерно за **последний
час**), сгруппированных по Steam ID, с указанием модуля, сработавшего для
каждого из них.

```bash
ssac.detections
```

> ℹ️ **Обнаружения хранятся только в памяти.** Они не переживают перезапуск
> сервера. Баны переживают — они хранятся в MySQL. Используйте ваши вебхуки
> Discord как постоянную запись обнаружений.

### `ssac.ban` / `ssac.unban`

```
ssac.ban <steamid> [r=<reason>] [d=<duration>]
ssac.unban <ban-id>
```

| Аргумент | Описание |
| -------- | ----------- |
| `<steamid>` | SteamID64 цели (17 цифр). |
| `r=<reason>` | Причина бана. Заключите в кавычки, если она содержит пробелы. По умолчанию `No reason provided`. |
| `d=<duration>` | Длительность бана, составленная из частей `d` / `h` / `m` / `s` — например, `7d`, `12h30m`, `1d6h`. Не указывайте её для **перманентного** бана. |

```bash
ssac.ban 76561198000000000 r="Aimbot" d=7d
ssac.ban 76561198000000000                  # перманентный, без причины
ssac.unban 42                               # снять бан №42
```

Бан записывается в MySQL вместе с IP игрока (и его аппаратным ID, если он был
захвачен), и игрок немедленно кикается, если он онлайн, с вашим
[`BanMessage`](bans.md#ban-message). `ssac.unban` принимает **ID бана**, а не
Steam ID — его показывают и `ssac.detections`, и сообщение о бане в Discord, и
это же значение подставляется как `{ban_id}` в сообщение при кике, которое
видит игрок.

### `ssac.banwave` / `ssac.clearbanwave` / `ssac.pendingbans`

```bash
ssac.pendingbans     # кто в очереди и почему
ssac.banwave         # забанить всех прямо сейчас
ssac.clearbanwave    # отпустить всех
```

Ожидающие баны ставятся в очередь модулями обнаружения и обычно выполняются
по расписанию — см. [Баны и обнаружения](bans.md#ban-waves). Эти три команды
позволяют просмотреть очередь, сбросить её досрочно или очистить очередь,
которую вы считаете ложным срабатыванием.

### `ssac.go`

Переводит вас в режим наблюдателя и перемещает к игроку.

```bash
ssac.go                       # игрок, обнаруженный последним
ssac.go 76561198000000000     # конкретный игрок
```

Без аргумента команда следует за последним обнаружением, что удобно при
реакции на оповещение. С указанным Steam ID она нацеливается на этого игрока
и выводит распознанное имя, чтобы вы могли убедиться, что взяли нужного
человека.

### `ssac.command`

Выполняет консольную команду от вашего имени и фиксирует, что ssAntiCheat её
санкционировал, чтобы модуль защиты администраторов не пометил вас за её
использование.

```
ssac.command <reason> <command...>
```

```bash
ssac.command investigating_dupe giveitemnum 1 1 0 0
```

Первый аргумент — это свободный текст причины для журнала аудита; всё, что
идёт после, — это выполняемая команда.

### `ssac.testdetection`

Создаёт **симулированное** обнаружение, чтобы вы могли проверить конвейер
дашборда, не дожидаясь настоящего читера. Требует, чтобы
[`Dashboard.Enabled`](configuration.md#dashboard) было `true`.

```
ssac.testdetection [steamid] [module]
```

```bash
ssac.testdetection                              # обнаружение для себя (из внутриигровой консоли)
ssac.testdetection 76561198000000000 AutoLoot   # для конкретного игрока, с меткой AutoLoot
```

Выполненная без аргументов из внутриигровой консоли, команда нацеливается на
**вас**, поэтому строка на дашборде показывает настоящее имя, племя и
позицию. Тестовые события помечаются как симулированные и исключаются из
статистики реальных обнаружений. Они не отправляются в Discord и никого не
банят.

## Чат-команды {#chat-commands}

Вводятся во внутриигровом чате, доступны только администраторам, с префиксом
[`CommandPrefix`](configuration.md#top-level-keys) (по умолчанию `!`). Там,
где команда принимает `<steamid>`, вы можете опустить его, и команда
подействует на **того, на кого вы смотрите**.

Названия распознаются точно так, как написано ниже, включая регистр.

### Расследование

| Команда | Описание |
| ------- | ----------- |
| `!esp` | Переключить ESP для себя. |
| `!espPlayers` | Переключить ESP игроков: имя, здоровье и текущее оружие над каждым игроком. |
| `!EspStruct` | Переключить ESP построек. |
| `!espset <name>` | Подсвечивать постройки, чьё имя чертежа содержит `<name>`, в дополнение к списку [`Structure ESP`](configuration.md#admin-esp). |
| `!espHideEmpty` | Скрыть пустые контейнеры в ESP построек. |
| `!tracers` | Отрисовать каждый ближайший выстрел линией трассера, окрашенной в зависимости от того, в какую часть тела он попал. Самый полезный инструмент для оценки помощи в прицеливании на глаз. |
| `!vanish` | Переключить собственную невидимость. |
| `!spawn` | Возродиться в текущей точке обзора, затем включить творческий режим, невидимость для врагов и полёт. |
| `!cloud <steamid>` | Вывести себе список загруженных (tribute) предметов игрока. |

`!esp` — это главный переключатель — `!espPlayers` и `!EspStruct` отрисовываются
только пока ESP включён для вас.

### Взаимодействие

Эти команды действуют на подозреваемого напрямую. Используйте их осознанно:
они видны игроку и могут спугнуть читера, по которому вы ещё собираете
доказательства.

| Команда | Описание |
| ------- | ----------- |
| `!unequip <steamid>` | Снять с игрока надетую броню. |
| `!dropweapon <steamid>` | Заставить игрока выронить оружие в руках. |
| `!jump <steamid>` | Заставить игрока подпрыгнуть. |
| `!punch <steamid>` | Активировать ракетный удар тек-перчатки игрока. |
| `!tekjump <steamid>` | Активировать ускорение тек-нагрудника игрока. |
| `!requestjoin <steamid>` | Отправить игроку поддельное приглашение в племя. |
| `!outofrange <steamid>` | Показать игроку клиентское уведомление «out of range». |
| `!playpoopsound <steamid>` | Проиграть игроку звук «poop». |
| `!playdeathsound <steamid>` | Проиграть игроку звук смерти. |

> ℹ️ **Каждое действие администратора логируется.** Чат-команды администратора
> записываются в локальный файл журнала и публикуются в
> [`AdminTrollingWebhook`](configuration.md#webhooks) с указанием
> действовавшего администратора, цели и местоположения — так что права
> администратора остаются подотчётными.
